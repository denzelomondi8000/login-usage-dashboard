# App Flow Document

## Onboarding and Sign-In/Sign-Up

When a brand-new user first arrives, they land on the public entry point of the application. This landing page presents clear calls to action for signing in or creating a new account. If the user chooses to sign up, they are directed to the sign-up page where they enter their email address, create a password, and submit the form. The system uses Better Auth to validate the inputs and then persists the new user record in the PostgreSQL database via Drizzle ORM. Once registration succeeds, the user’s session is created, and they are automatically redirected to the dashboard. If an existing user clicks the sign-in link, they arrive at a form asking for email and password. Submitting valid credentials triggers Better Auth’s sign-in route, sets a secure session cookie, and directs the user to the dashboard. On the sign-in form, there is also a “Forgot password?” link that sends the user to a password recovery page. After entering their email there, a secure email is sent with a reset link. Following that link leads to a reset password page where the user chooses a new password. Completing this flow logs the user in and takes them back to the dashboard. To sign out, the user clicks a sign-out button in the header, which calls the sign-out API route, clears the session, and brings the user back to the public landing page.

## Main Dashboard or Home Page

Once authenticated, the user lands on the dashboard page. This default view displays a persistent layout with a sidebar on the left and a header at the top. The sidebar holds navigation links to the dashboard and settings sections. The header shows the user’s name or avatar, a theme toggle for light and dark mode, and a sign-out button. The main content area fills the remainder of the screen and is populated with the user’s usage details. At the top of the content area are summary cards that highlight metrics such as current usage, usage limit, or remaining quota. Below the cards is a data table presenting a history of usage records, and to the side is an interactive chart tracking usage trends over time. From this dashboard, clicking any navigation link in the sidebar or header seamlessly transitions the view to the corresponding section without a full page reload.

## Detailed Feature Flows and Page Transitions

When the user visits the dashboard, the server component fetches the current user’s session information via Better Auth. Using the user ID, a Drizzle ORM query retrieves the usage records from the `usage` table in PostgreSQL. These data objects are then passed to UI components—like the summary cards, table, and chart—as props and rendered in the main content area. If the user clicks on a specific record in the table, the application opens a detail view overlay or navigates to a record detail page, showing additional information for that specific entry. Theme changes happen instantly when the user toggles the switch in the header; the application stores the preference in local storage and updates the appearance across all pages. When the user selects the settings link, the layout smoothly swaps the dashboard content for the settings page, where they can manage account details. All internal transitions use Next.js App Router’s client-side navigation, resulting in quick, fluid page changes.

## Settings and Account Management

In the settings area, the user can update their personal information and account preferences. The settings page is protected, so the application verifies the session before rendering. Once on this page, the user can change their email address or password. Submitting a change triggers the appropriate Better Auth API endpoint, which validates and updates the credentials. Users can also configure notification preferences for alerts when they approach their usage limits. These preference updates are saved to the database via Drizzle ORM. If the application supports subscription tiers, the subscription settings section allows the user to view their current plan and upgrade or downgrade. Clicking a plan option integrates with the billing API to process payments and adjust the user’s role in the system. After saving changes, a confirmation banner appears at the top, and the user can navigate back to the dashboard via the sidebar.

## Error States and Alternate Paths

If the user enters invalid credentials on sign-in or sign-up forms, inline error messages appear under the relevant input fields explaining the issue. Network connectivity problems show a banner at the top indicating that the request failed and advising the user to check their connection. If an unauthenticated user attempts to access a protected page like the dashboard or settings, the application automatically redirects them to the sign-in page. During data fetching on the dashboard, if no usage data is found for the user, an empty state appears with a friendly message explaining that no usage records exist and suggesting the user generate usage by interacting with the application’s core features. If the session expires, any API call returns an unauthorized error and triggers a client-side redirect back to the sign-in page with a message about the expired session. In the password recovery flow, if the reset token is invalid or expired, the user sees an error explaining that they must request a new reset link.

## Conclusion and Overall App Journey

From the moment a new visitor lands on the app, they are guided to create an account or sign in. Once authenticated, they step into a dashboard that instantly shows their usage metrics in a clear, card-table-chart layout. They can explore usage trends, click through individual records for details, and adjust their preferences from the settings section. At any point, they can toggle themes or sign out. Error messages and redirects keep them on track if something goes wrong, like invalid input or an expired session. Over time, the user returns here to monitor usage, manage their account, and maintain control over their consumption metrics in an intuitive, reliable experience.
